# Numahop technical documentation. 

This documentation is using mdbook and schemaspy. 
Note: This documentation is very incomplete and in its early stages.

## Dependencies

### Building (required)

- mdbook v0.5.2
- mdbook-arborium v0.1.0
- mdbook-i18n-helpers v0.4.0

Some of these might be present in your systems package manager (not garanted).

To install the related mdbook dependencies you can use the `cargo` command from
your rust installation like this: 
```bash
# installing the rustup toolchain manager (only if you have not a rust toolchain present)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh 

# Get an up to date toolchain
rustup update

# Install the mdbook deps
cargo install mdbook mdbook-arborium mdbook-i18n-helpers 

# If you want to uninstall the rust environement later
rustup self uninstall
```

### Developping

Most dependencies are optional depending on the task at hand.

For updating the database schemaspy:
- A running NumaHOP instance.
- mariadb-j-connector jarfile (provided in `vendor`)
- OpenJdk17
- schemaspy jarfile (provided in `vendor`)
- curl

For updating the graphs:
- node24
- @mermaid-js/mermaid-cli v11.* (mermaid compiler)

```bash
npm i -g @mermaid-js/mermaid-cli
```

For updating the api section:
- python3 with the `tree_sitter`, and `tree_sitter_language_pack` libraries.
- A check-out of the nuamahop source.

For running the scripts:
- bash

For serving localy:
- livereload (watch build result and serve it on localhost)
- watchexec (watch and rerun build scripts when source changes)

## Generated documentation.

Some part of the documentation is generated and needs a runnning Numahop
Instance and/or a clone of the source code to the version for which you want to
generate the documentation. In the `scripts` folder there are the scripts used
to update the generated part of the documentation. In the `gen` folder there
are the cached generated documentation pieces allowing to build for the latest
NumaHOP release.

The build process is as folows: 
- Build the source tree of the book from the markdown in src and the generated markdown files in the `include` directory.
- Builds the mdbook book.
- Patch in the generated html files in the build directory.

## Building and consulting offline. 

The `setup` rule of the makefile fetches the correct mdbook version, mdbook
preprocessors, and the schemaspy needed jars. But everything is compiled if you
don't trust fetching the compiled versions from the web you can fetch them
yourself. And place them in the vendor folder.

```bash
just build
just open
```
